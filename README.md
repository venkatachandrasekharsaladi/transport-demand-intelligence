# Transport Intelligence

## Project overview

This MSc Artificial Intelligence prototype forecasts hourly passenger demand for
bus routes, analyses demand patterns, simulates fleet allocation and presents the
results through a React dashboard. The Python project remains the intelligence
layer; the frontend consumes static JSON generated by Python.

The original notebook remains preserved as research evidence. Reusable pipeline
and agent code is now available in the Python modules, while the dashboard is
implemented in `frontend/`.

## Project architecture

- **Forecasting Agent:** predicts hourly route demand from a trained model.
- **Demand Analysis Agent:** identifies peaks, route rankings and unusual demand.
- **Operations Planning Agent:** simulates fleet allocation under constraints.
- **Gemini AI Coordinator:** coordinates outputs and explains recommendations.
- **React Dashboard:** presents forecasts, analysis, planning and explanations.

## Requirements and setup

Python 3.12 is required. In PowerShell, create and activate a virtual environment,
then install the dependencies:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## Gemini configuration

Copy `.env.example` to `.env` if needed and set `GEMINI_API_KEY` to your own key.
The `.env` file is ignored by Git. `GEMINI_MODEL` defaults to
`gemini-3.6-flash`. Stage 1 does not make Gemini API calls.

## Dataset

Copy the existing eight-week NYC MTA hourly bus ridership CSV to:

```text
data\mta_ridership.csv
```

The CSV must contain `transit_timestamp`, `bus_route` and `ridership` columns.
The validator calculates actual statistics, preserves all records and warns about
data-quality issues.

## Run dataset validation

```powershell
python -m core.data_processing
```

This command validates `data\mta_ridership.csv` relative to the project root. It
does not download data or create synthetic records.

## Generate dashboard data

The model artifact is trained from the existing CSV using the latest one-hot
Random Forest implementation migrated from the notebook:

```powershell
python -m core.train_model
python -m core.export_dashboard_data
```

The exporter writes these real model outputs to `frontend/public/data/`:

- `overview.json`
- `forecast.json`
- `demand_analysis.json`
- `fleet_plan.json`

The exporter fails if the model artifact is missing and never generates fallback
forecasts. Fleet values remain simulation assumptions and require human review.

## Run the React dashboard locally

```powershell
cd frontend
npm install
npm run dev
```

The frontend loads JSON using `import.meta.env.BASE_URL`, so it works from the
Vite development server and GitHub Pages.

## Build for production

```powershell
cd frontend
npm run build
```

## GitHub Pages deployment

The workflow at `.github/workflows/deploy.yml` runs on pushes to `main`. It sets
`VITE_BASE_PATH` automatically to `/<repository-name>/`, builds `frontend/dist`,
and deploys it with the GitHub Pages deployment actions.

In the GitHub repository:

1. Open **Settings → Pages**.
2. Set **Source** to **GitHub Actions**.
3. Ensure Actions are allowed to write Pages artifacts.
4. Push to `main`.

No GitHub username or repository name is hardcoded. If building manually for a
specific repository URL, set the repository base path before building:

```powershell
$env:VITE_BASE_PATH = "/repository-name/"
npm run build
```
